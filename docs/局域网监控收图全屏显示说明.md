# 局域网监控收图「能显示但不铺满」排查与优化

## 结论

原代码能出图，但画面不是全屏，主要不是“没收着”，而是**显示方式不对**，再叠加**拼包/定帧不稳**。

## 原因

1. **只赋了底图，没有按画板尺寸缩放**  
   `画板_显示屏幕信息.底图 ＝ 收图缓冲` 会按原图像素贴在左上角。  
   你虽然声明了 `显示宽度 / 显示高度 / 比例 / 左边距 / 顶边距`，但从未计算、也从未用来绘制，所以控件多大，图也不会自动铺满。

2. **缓冲变量不能是局部变量**  
   `收图缓冲`、`上次刷新时间` 写在 `.局部变量` 里时，每次「数据到达」都会重置，半包拼不连续。偶发整包能出图，但残缺 JPEG 常被解成“只有上半截”的假图，看起来像非全屏。

3. **用长度阈值 + 载入图片 判完整帧不可靠**  
   `缓冲长度 ＜ 20000` 就返回、够长就 `载入图片`：半包 JPEG 有时也能“载入成功”，得到残缺画面。

## 优化要点（已写入可粘贴代码）

| 项 | 做法 |
|---|---|
| 拼包 | `收图缓冲` / `最近一帧` / `全屏铺满方式` 必须用**程序集变量**（易语言静态变量不跨子程序共享） |
| 定帧 | JPEG 找 `FFD8`…`FFD9`；BMP 按文件头长度截取，避免半包残图 |
| 全屏 | `StretchBlt` 按画板宽高拉伸；`全屏铺满方式=1` 强制铺满 |
| 重画 | 绑定画板「重画」事件，防止被遮挡后画面丢失 |
| 降频 | 保留约 120ms 刷新间隔，可按需删 |

完整可粘贴源码：`docs/易语言_局域网监控收图全屏显示.txt`

```text
监控收图_画板全屏显示 (画板句柄, 图句柄, 宽, 高, 1)
```

## 若仍不满屏

先确认被控端发的就是整屏截图（分辨率是否等于对方桌面）。若对方本身只抓了窗口/区域，接收端无法“变出”全桌面。接收端把 `全屏铺满方式` 设为 `1` 可至少铺满本地画板。
